# Google Takeout "Maps" formats — parser reference

Google Takeout is inconsistent: the same logical field is spelled differently
across export versions, locales, and contribution types. This document records
the field-name variants the parsers in `src/Parser/` resolve, and the shape of
each fixture in `fixtures/`. It is a reference for anyone extending the parsers
or debugging a real export.

Field resolution is done by `PropertyFinder`, which matches keys
**case-insensitively** and supports **dot-notation** for nested objects. So
`location.name` and `Location.Name` resolve identically, and a variant list
only needs to enumerate distinct *spellings* (different separators or words),
not different casings.

> [!NOTE]
> This list is built defensively from observed exports, not from an official
> Google schema. A real export may surface further variants — adding one is
> just a new entry in the relevant `*_KEYS` constant. The authoritative-schema
> uncertainty is tracked as an open question in `ARCHITECTURE.md`.

## Reviews (`ReviewsParser`)

Takeout normally emits reviews as a GeoJSON `FeatureCollection`; a `reviews`
wrapper, a bare list, and a single object are also accepted.

| Field        | Variants resolved |
|--------------|-------------------|
| Rating       | `five_star_rating_published`, `star_rating`, `Star Rating`, `Star_Rating_Published`, `stars`, `rating` |
| Review text  | `review_text_published`, `review_text`, `Review Text`, `Published_Review`, `comment`, `text` |
| Date         | `published_date`, `review_date`, `date`, `Date`, `published` |
| Place name   | `location.name` (nested), `name`, `place_name`, `title` |
| Address      | `location.address` (nested), `address`, `place_address`, `formatted_address` |
| URL          | `google_maps_url`, `googleMapsUrl`, `maps_url`, `url`, `place_url` |
| Coordinates  | GeoJSON `geometry.coordinates` as `[lng, lat]`; or flat/nested latitude & longitude |

## Starred / Saved places (`StarredParser`)

GeoJSON `FeatureCollection`, like reviews, but with no rating and no review
text. Same name / address / URL / coordinate variants as reviews, plus
capitalized spellings (`Title`, `URL`, `Address`) seen in some exports.

| Field | Variants resolved |
|-------|-------------------|
| Date  | `date`, `Date`, `published_date`, `saved_date`, `created` |

## Photos (`PhotosParser`)

Follows the Google Photos export shape: a `photos` wrapper, a bare list, or a
single object. The photo **title** becomes the contribution's place name.

| Field       | Variants resolved |
|-------------|-------------------|
| Title       | `title`, `name`, `filename`, `photo_title`, `caption` |
| View count  | `imageViews`, `image_views`, `view_count`, `views`, `photo_views`, `viewCount` |
| Date        | `photoTakenTime.timestamp`, `photoTakenTime.formatted`, `creationTime.timestamp`, `creationTime.formatted`, `photo_taken_time`, `creation_time`, `date`, `timestamp` |
| Coordinates | `geoDataExif.latitude` / `geoDataExif.longitude`, falling back to `geoData.*` then flat keys |

## Questions (`QuestionsParser`)

A `questions` wrapper, a GeoJSON `FeatureCollection`, a bare list, or a single
object. The question text is stored in the contribution's `reviewText` field.

| Field         | Variants resolved |
|---------------|-------------------|
| Question text | `question_text`, `Question Text`, `question`, `Published_Question`, `text`, `body` |
| Place name    | `place_name`, `location.name` (nested), `name`, `title` |
| Address       | `place_address`, `location.address` (nested), `address`, `formatted_address` |
| URL           | `place_url`, `placeUrl`, `google_maps_url`, `googleMapsUrl`, `maps_url`, `url` |
| Date          | `date`, `published_date`, `asked_date`, `question_date`, `created`, `timestamp` |

## Normalization rules (all types)

- **Coordinate order.** GeoJSON `geometry.coordinates` is `[longitude,
  latitude]` — longitude first. `Coordinates::resolve()` is the single place
  that knows this.
- **Null Island.** Any record resolving to latitude 0 *and* longitude 0 is
  dropped — Takeout emits 0,0 when it has stripped a location.
- **Coordinate precision.** Latitude/longitude are rounded to 7 decimal places.
- **Dates.** ISO-8601 (with or without a timezone), bare `Y-m-d`, and Unix
  timestamps (seconds or milliseconds, often quoted) are all accepted and
  normalized to UTC. An absent or unparseable date becomes the Unix epoch.

## Fixture files

The files in `fixtures/` are realistic, hand-built samples that exercise the
variants above. `fixtures/takeout-sample.zip` bundles all four into a
Takeout-style directory layout and is regenerated by
`php scripts/build-sample-zip.php`.

| Fixture          | Records | Notes |
|------------------|---------|-------|
| `reviews.json`   | 6       | Spreads the rating/text/date/name/URL variants across features; one feature sits at 0,0 to verify skipping (5 parse). |
| `starred.json`   | 4       | Nested vs. flat names; capitalized `Title`/`URL`/`Address` on one feature. |
| `photos.json`    | 4       | Covers the view-count and date variants; one photo carries only `geoData` (no `geoDataExif`) to exercise the coordinate fallback. |
| `questions.json` | 3       | Covers question-text and place-URL variants; one question names its place only via a nested `location` object. |
